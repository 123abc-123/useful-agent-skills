# 案例：时间和实体泄漏审计

## 情境

一个用户转化模型按行随机切分训练集和测试集。表中包含事件时间、用户标识、聚合特征和最终转化标签，但目前无法确认特征的可用时点。

## 运行方法

1. 用 [`data-leakage-review`](../prompts/data-leakage-review.prompt.md) 填入预测实体、预测时点、标签和数据相关文件。
2. 让 Agent 只读检查数据查询、特征生成、切分和评测代码。
3. 对需要重复执行的仓库流程，安装 [`data-leakage-audit`](../../skills/data-leakage-audit/SKILL.md)。
4. 人工核对 Agent 引用的文件、SQL 字段和样本标识。

## 合格产出

- 写清预测发生时真正可用的信息；
- 分别检查目标、时间、用户交叉、重复样本、预处理和调参泄漏；
- 每个判断指向具体证据，无法验证的项标为未知；
- 给出最小修复以及修复前后使用同一口径的重跑计划。

如果报告只说“可能有泄漏”、只比较一个总体分数，或者没有定位到数据与代码位置，本次演练不通过。
